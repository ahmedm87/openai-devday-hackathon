# Contributing

1. Pull the latest `main` before starting work.
2. Create a branch such as `feature/demo-flow` or `fix/setup`.
3. Keep commits focused and describe what changed.
4. Run the relevant checks and mention the results in your pull request.
5. Ask a teammate to review before merging.

Use GitHub Issues to record tasks, bugs, and decisions. Include enough context for another teammate to pick up the work.

Never commit credentials or private data. If an API key is accidentally committed, revoke it immediately.
